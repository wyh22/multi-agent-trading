# v1.4 Validation

This document records the validation boundary for the public recruiting branch.

## Automated checks

GitHub Actions runs the following checks on Python 3.11 and 3.12:

- editable install with `.[agent,dev]`;
- `python -m compileall -q tradingagents service scripts`;
- import smoke tests for the API, MCP server, discovery, evaluation and backtest modules;
- `pytest -q`;
- Docker image build.

## Regression coverage

The current suite covers:

- conversation thread persistence and reset;
- ticker normalization and chat routing;
- `/chat`, history/reset and browser UI routes;
- Finance MCP / RAG architecture wiring;
- external MCP tool allowlist behavior;
- Point-in-Time filtering for research data;
- parallel graph wiring;
- real graph-construction smoke test with injected analyst tool groups;
- sector-first discovery, regime-aware Style weights and optional ML reranking;
- representative research-pool scoring without PE/ROE/quality leakage;
- candidate-context anti-confirmation guard and checkpoint isolation;
- `/research-pool` / conversational research-pool / 7-Agent handoff wiring;
- typed claim extraction, fallback classification and budget-aware context compression;
- Agent Evaluation metrics;
- deterministic outcome-backtest metrics.

## A-share data-source boundary

The core path is intentionally centered on:

- BaoStock for A-share OHLCV, valuation context and realized-return windows;
- AKShare public interfaces for financial statements, macro data, market news and management-holding context;
- CNInfo for official company announcements.

Optional external providers remain non-essential extensions and are not required for the core A-share workflow.

## Not covered by offline CI

- live LLM calls that require user credentials;
- live external third-party MCP servers;
- upstream data-provider availability, throttling or website/API changes;
- end-to-end Docker Compose startup against external registries and live networks.

Offline regression success is an engineering reproducibility signal, not a claim that every external service is production-validated.


## Validation philosophy

Public CI is designed to validate deterministic engineering invariants without secrets. It intentionally avoids treating live LLM output as the primary test oracle because model responses, network availability and third-party data can be non-deterministic.

The goal of the offline suite is therefore to answer a narrower but reproducible question: **does the repository still satisfy its declared architecture, state contracts, PIT constraints, import boundaries and deterministic evaluation logic?**
